01 · The goal

Make API test generation reviewable.

Start with an existing Swagger or OpenAPI contract. Let a person decide what is safe and useful before any API request is made.

  • Analyze
    Derive stable test cases from contract facts.
  • Review
    Inspect evidence, inputs, risks, and uncertainty.
  • Approve
    Bind approval to the selected plan revision.
  • Verify
    Run through explicit gates and summarize observations.

Core messageThis automates the repeatable mechanics while keeping test selection and execution under human control.

02 · The workflow

Approval is part of the architecture.

01ContractSwagger / OpenAPI input
02EvidenceCases, samples, pointers
03Human reviewSelect and approve
04Guarded runTarget and execution gates
05ResultRedacted record and summary

The demo is deterministic. OpenAI drafting is optional, excluded here, and has not been called live.

Review one case before running it.

Fetch the current contract, then select only TC-GETINVENTORY-POS-200 and approve generation.

curl -fsSL https://petstore.swagger.io/v2/swagger.json -o /tmp/petstore-demo-swagger.json
npx tsx src/cli.ts guide \
  --spec /tmp/petstore-demo-swagger.json \
  --objective "Validate the Petstore inventory read operation" \
  --out tests/generated/petstore-demo-inventory.spec.ts \
  --audit /tmp/petstore-demo-guided.jsonl

Guide prompts: select the case ID, inspect evidence, type APPROVE. No API-under-test request yet.

11 · Limits and safeguards

Transparent about what is not covered.

No model call

The demonstrated path is deterministic. No private data is sent to an external model.

No public writes

Petstore order creation and cleanup were tested on loopback only.

Not every case runs

Missing inputs, auth, or safe error triggers stay in manual review.

Failures stay visible

findByStatus returned HTTP 200 but failed schema validation; it is not a pass.

Reports show recorded outcomes and evidence; they do not certify every operation or infer unsupported causes.

12 · Discussion

What would make this useful to your team?

Is it AI-driven?

The demonstrated flow is deterministic. No live OpenAI call.

Why not automate every case?

Missing inputs, auth, serialization, or success criteria stay visible for review.

Production-ready?

No. It is a project prototype; a colleague clean-setup acceptance run remains.

What is next?

Choose a pilot API, useful cases, and measurable acceptance criteria.

Ask: Which API and workflow should be the next pilot, and what evidence would your reviewers need?
