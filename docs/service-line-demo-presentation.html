05 · Input 1 · Petstore

Fetch the spec, then analyze it.

PowerShell commands from the repository root:

$specPath = Join-Path $env:TEMP 'petstore-demo-swagger.json'
$planPath = Join-Path $env:TEMP 'petstore-demo-plan.md'
curl.exe -fsSL https://petstore.swagger.io/v2/swagger.json -o $specPath
npx.cmd tsx src/cli.ts analyze --spec $specPath --out $planPath
Invoke-Item $planPath
What happens--spec points to the downloaded file. analyze validates it and writes the reviewable case plan. No API operation is sent.

08 · Manual-case generation

Generate a review item. Do not guess its trigger.

TC-PLACEORDER-NEG-400 · POST /store/order
  1. Define a safe input for the documented invalid-order scenario.
  2. Use only an authorized isolated environment and test data.
  3. Confirm HTTP 400 and review the documented error response.

The analyzer writes this proposal, its expected outcome, and open questions into the Markdown plan as manual review.

Optional AI proposalguide --ai-draft-cases requires explicit SEND TO OPENAI consent. Drafts are separate review documents, never executable test code.

09 · Detailed test steps

Inspect the case before automation.

TC-GETINVENTORY-POS-200 · GET /store/inventory

Spec evidence: /paths/~1store~1inventory/get/responses/200

  • Expected: HTTP 200
  • Auth: declared API key
  • Risk: read-only
  • Evidence: response 200 JSON Pointer

Numbered test steps

  1. Construct request URL and parameters.
  2. Set headers and environment-based auth.
  3. Send the GET request.
  4. Assert exact documented status.
  5. Check response content type.
  6. Validate supported response-schema constraints.

Reviewer questionAre the input, auth, and checks appropriate for this environment?

11 · Convert case to code

Approved case → Playwright TypeScript.

The guided workflow writes tests/generated/petstore-demo-inventory.spec.ts; the reviewer does not hand-translate the case. Structural excerpt from the generated case/step loop:

for (const testCase of cases) {
  test(`${testCase.id}: ${testCase.title}`, async ({ request }, testInfo) => {
    let response: APIResponse | undefined;
    for (const [index, step] of testCase.steps.entries()) {
      await test.step(`${index + 1}. ${step.action}`, async () => {
        if (step.kind === "assert-status") expect(response!.status()).toBe(testCase.expectedStatus);
      });
    }
  });
}

What carries throughStable ID, numbered steps, exact documented status, schema checks, and approved plan binding.

  • Assertions: exact status, media type, schema
  • Safety: warnings, mutation default, plan binding
Get-Content tests/generated/petstore-demo-inventory.spec.ts
npm.cmd run typecheck
npx.cmd playwright test --list tests/generated/petstore-demo-inventory.spec.ts --reporter=list

Typecheck and --list validate source and discovery; neither sends the API request. Do not edit an approved artifact in place.

13 · Guarded execution

Run only the approved artifact.

Terminal A: start the loopback service and leave it running: npm.cmd run mock:petstore. Use Terminal B for the run command.

$env:API_KEY_API_KEY = 'local-mock-key'
$inventoryResults = Join-Path $env:TEMP 'petstore-demo-results.json'
$inventoryReport = Join-Path $env:TEMP 'petstore-demo-report.html'
$inventoryAudit = Join-Path $env:TEMP 'petstore-demo-run.jsonl'
npx.cmd tsx src/cli.ts run --base-url http://127.0.0.1:4010/v2 --file tests/generated/petstore-demo-inventory.spec.ts --results $inventoryResults --html-report $inventoryReport --audit $inventoryAudit
1Confirm target is authorized and non-production
2Confirm mock authentication is configured
3Approve this execution
0Public API mutations

Enter AUTHORIZED NON-PRODUCTION, AUTHENTICATION CONFIGURED, and RUN APPROVED when prompted. The expected mock outcome is one HTTP 200 pass.

14 · Reporting

Run evidence in three useful forms.

HTML report

Counts and rows by case ID, outcome, method/path, expected/actual HTTP, duration, and redacted diagnostic.

$inventoryReport

JSON results

Machine-readable case outcomes plus available numbered-step evidence.

$inventoryResults

Audit log

Plan, approval, target, and run events without raw response bodies or credential values.

$inventoryAudit

Readable summary

Summarize the saved JSON without sending another request.

npx.cmd tsx src/cli.ts summarize --results $inventoryResults
Expected demo shape: 1 case · 1 passed · 0 failed · 0 skipped

Interpret carefullyCompare recorded HTTP status and assertion step. A summary reports observations; it does not invent a cause.
